# Localization

Chimera's interface is available in **English** (`en`) and **Lithuanian**
(`lt`). Model output, your own content, model names, URLs and technical
identifiers (e.g. `llama-server`) are never translated.

## How the language is chosen

1. A saved choice wins (the account's language once signed in, otherwise the
   browser's `localStorage`).
2. On a first visit, the browser's preferred languages (`navigator.languages`)
   are checked; `lt-*` selects Lithuanian.
3. Otherwise English.

Switching applies instantly (no reload), updates `<html lang>` (screen readers,
spellcheck, hyphenation) and is stored on the account when signed in, so it
follows the user to other devices. A choice made on the sign-up screen becomes
the new account's language; at sign-in the account's saved language wins.

The language selector is in **Settings → Appearance**, **Settings → Account**,
and at the top of the sign-in and registration screens.

## Implementation

- **Library:** [`i18next`](https://www.i18next.com/) + `react-i18next`. Mature,
  small, works offline, and its plural support is built on
  `Intl.PluralRules`, which handles Lithuanian's `one / few / many / other`
  categories correctly (1 pokalbis, 2 pokalbiai, 10 pokalbių, 21 pokalbis,
  1,5 pokalbio).
- **Catalogs:** `frontend/src/i18n/locales/<lang>/<namespace>.json`, bundled by
  Vite. Namespaces: `common`, `auth`, `chat`, `sidebar`, `models`,
  `knowledge`, `prompts`, `settings`, `account`, `admin`, `web`, `errors`.
- **Typed keys:** `src/i18n/i18next.d.ts` types `t()` against the English
  catalogs, so a misspelled key fails `tsc`.
- **No sentence assembly:** strings are whole sentences with `{{placeholders}}`
  (and, where markup is needed, `<tags>` rendered by `<Trans>`), so word order
  and grammatical case can differ per language.
- **Dates, numbers, sizes:** `Intl.DateTimeFormat`, `RelativeTimeFormat`,
  `NumberFormat` (including byte units) and `ListFormat` with the active
  language (`src/lib/time.ts`, `src/lib/utils.ts`).
- **Errors:** the API returns `{"detail": {"code", "message", "params"}}`. The UI
  translates the `code` (`errors:<code>`; provider failures use
  `errors:provider.<code>`; web failures are `web.*` codes such as
  `web.blocked_address` → `errors:web.blocked_address`). The English `message`
  is only a fallback for unknown codes. Text that comes from a model server,
  page content, page titles and URLs are shown verbatim, never translated.

## Guardrails (run in `npx vitest run`)

`src/i18n/i18n.test.ts` fails the build when:

- a language is missing a key or has an extra one,
- a plural key lacks a category the language needs (`en`: one/other;
  `lt`: one/few/many/other),
- placeholders or `<tags>` differ from the English source,
- a component contains an obvious hardcoded English string (best-effort scan of
  JSX text and `aria-label`/`title`/`placeholder`/`label` attributes; mark a
  deliberate exception with `i18n-ignore` in a comment on that line).

It also checks Lithuanian plural output for 0, 1, 2, 10, 11, 21, 22, `Intl`
formatting in both languages, and that error codes render in both languages.

## Editing a translation

Edit the JSON file, keeping keys, `{{placeholders}}` and `<tags>` unchanged, and
run `cd frontend && npx tsc -b && npx vitest run`. Follow
[the glossary](i18n-glossary.md) so terms stay consistent.

## Adding a language (e.g. German)

1. Copy `src/i18n/locales/en` to `src/i18n/locales/de` and translate the values.
   For plural keys, provide every category `Intl.PluralRules("de")` uses
   (check with `new Intl.PluralRules("de").resolvedOptions().pluralCategories`).
2. In `src/i18n/resources.ts`, import the files, add `de` to `LANGUAGES`, a
   native name to `LANGUAGE_NAMES` (`"Deutsch"`), and a `de` entry to
   `resources`.
3. Add the plural categories to `REQUIRED_PLURALS` in `src/i18n/i18n.test.ts`.
4. Allow the code on the server: add it to `LANGUAGES` in
   `backend/chimera/services/auth.py` and to the `Language` literal in
   `backend/chimera/api/schemas.py`.
5. Run the tests.

## Defaults that users see

The welcome greeting, example prompts and all built-in labels are translated.
No prompt library entries are seeded. The **default system prompt is empty**
and fully editable; whatever you write there is sent to the model as written,
in any language.

## Native review

The Lithuanian text was written by the AI assistant that built this feature,
not by a native speaker. It should be reviewed by a native Lithuanian speaker;
see the list of uncertain phrases in [i18n-glossary.md](i18n-glossary.md).
